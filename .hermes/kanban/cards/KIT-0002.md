## Outcome

A second tool (candidate: **UUID / ID** generator, pattern `generate`) implemented by **cloning the KIT-0001 golden template**, proving the pattern scales without redesign.

## Context

Base64 remains the reference implementation, but it is not the product center
and does not block parallel tool work. This slice must prove a different UI
pattern instead of cloning transform-specific layout mechanically.

## Acceptance criteria

- [ ] Follow the current shared UI/platform contracts; do not copy Base64-specific controls.
- [ ] New tool uses same shell, tokens, and interaction honesty rules from `docs/architecture/tool-pattern.md` (post-KIT-0001).
- [ ] Core logic + catalog entry + UI; tests for core.
- [ ] Design frame for the tool identified in `design.pen` before coding.

## Non-goals

- Redesigning the shell.
- Building more than one additional tool in this card.

## Architecture notes

- Same package boundaries as KIT-0001.
- Prefer `generate` pattern if UUID is chosen (options + generate), not force-fit into encode/decode split.

## Test plan

- Unit core; manual: generate, copy, theme/favorites still work.

## Security, privacy, and accessibility

- Same local-first baseline; no payload persistence unless a later privacy-reviewed card.
