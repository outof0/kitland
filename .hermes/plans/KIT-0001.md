## 1. Problem statement

Kitland’s public promise is calm, local-first, one-step tools. The landing
delivers that tone. The original Base64 **spike** did not:

- It does not read as the same product as `design.pen`.
- Controls do not tell a single honest story (live output + “Encode” that copies + extra Swap/Wrap).
- It is unsafe to clone as the template for 60+ tools.

This plan produces **one golden screen**, not more tools.

---

## 2. Goals / non-goals

### Goals

1. Design-faithful Base64 + shell at declared breakpoints.
2. Locked interaction model (section 3).
3. Template docs agents can follow without reinventing UX.
4. Minimal durable prefs: theme, favorites, sidebar collapse — **not** payload drafts.

### Non-goals

See card. Especially: no multi-tool build-out; no shadcn UI-foundation migration
as a side effect of this card.

## 3. Interaction model (current)

### 3.1 One sentence

> User pastes or types → result updates immediately → user copies or saves; mode chooses direction; chrome never pretends to “run” a second engine.

### 3.2 Control → behavior map

| UI control (design)   | Behavior                                                                                           | Notes                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Input textarea        | Source of truth; live `runBase64(mode, input)`                                                     | Debounce not required for Base64 at normal sizes; respect core max length |
| Output textarea       | Read-only derived value                                                                            | Empty when input empty                                                    |
| Mode Encode           | Select Encode; when a stable valid result fits the Encode input contract, move it into input first | A target-limit block retains the existing direction and explains why      |
| Mode Decode           | Select Decode; when a stable valid result fits the Decode input contract, move it into input first | Invalid alphabet → error state; no control-caused red flash               |
| Sample                | Set input to design sample; mode encode                                                            | From frame copy                                                           |
| Header Share input    | Create/copy a hash-only input link after explicit activation                                       | Disclosure: link contains input; do not share secrets                     |
| Input toolbar Copy    | Copy source input                                                                                  | Icon → check briefly and announce success                                 |
| Input toolbar Upload  | Load a UTF-8 text file into input                                                                  | Input only                                                                |
| Input toolbar Eraser  | Clear input                                                                                        | Pane-local; header does not duplicate it                                  |
| Output toolbar Copy   | Copy output                                                                                        | Icon → check briefly and announce success                                 |
| Output toolbar Save   | Download `.txt`                                                                                    | Filename: `encoded.base64.txt` / `decoded.txt`                            |
| Theme Dark/Light      | Set theme + persist                                                                                | Default dark                                                              |
| Star (header)         | Toggle favorite for current slug                                                                   | Persist                                                                   |
| Sidebar favorite star | Toggle that tool’s slug if available                                                               | Unavailable tools: no star action                                         |
| Search ⌘K             | Out of scope                                                                                       | Follow-up card                                                            |
| Center Swap           | Switch direction with the same safe transfer contract as the mode selector                         | Transform-only rail; disabled while processing                            |
| Wrap toggle           | **Out of v1**                                                                                      | CSS `white-space` wrap default OK                                         |

### 3.3 State model (conceptual)

```text
mode: 'encode' | 'decode'
input: string
result: ToolResult<string>   // derived, not stored
theme: 'light' | 'dark'      // persisted
favorites: string[]          // persisted slugs
sidebarCollapsed: boolean    // persisted
uiFlash: control-local copy/share check + announced text; concise error/info feedback
```

### 3.4 Error & empty

| Condition       | UI                                                                                      |
| --------------- | --------------------------------------------------------------------------------------- |
| `input === ""`  | Output empty; status “Ready”; no error banner                                           |
| Decode invalid  | `result.ok === false`; banner or inline error with message from core; status chip error |
| Input too large | Core error code; actionable message                                                     |
| Copy failure    | Actionable error feedback; status chip remains a stable transform state                 |

### 3.5 Why not explicit Run?

- Kitland principle: one step, one result; landing “paste, copy”.
- Design mock already shows simultaneous input/output filled.
- Explicit Run is valid for expensive tools (hash with iterations, network) — track as pattern variant later, not Base64.

### 3.6 Why Copy is pane-local

- Live conversion already makes the result visible; Copy is therefore an output
  action, not a disguised Encode/Decode action.
- Keeping Copy and Save in the output toolbar avoids duplicate controls and
  makes action scope obvious to sighted and keyboard users.

## 6. Manual test script (Verification)

1. Cold load `/explore/base64` — dark theme default (or last persisted).
2. Sample → output matches expected Base64 for sample.
3. Edit input → output updates without pressing a run action.
4. Output Copy → clipboard has output; invoked icon shows a short success state.
5. Mode Decode or center Swap with good Base64 → plain text without a validation flash.
6. Mode Decode with `@@@@` → error, no crash.
7. Clear → empty both.
8. Upload a small `.txt` into input → content appears.
9. Output Save → file downloads.
10. Star on → appears in Favorites; reload → still there; star off → removed.
11. Theme light → reload persists; toggle dark.
12. Landing CTA → arrives at Base64.
13. Resize 1280 / 900 / 390 — no page-level horizontal scroll; critical actions available.
14. Keyboard only: tab through Sample, Share, mode, Swap, input/output pane actions, star, and theme.

## 8. Risks & mitigations

| Risk                                             | Mitigation                                                                                                        |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Pencil MCP unavailable                           | JSON extract + export HTML; record method                                                                         |
| Direction change can exceed the next input limit | Retain the current direction and give a concise explanation; never surface a control-caused validation error      |
| Favorites empty vs design placeholders           | Empty state copy; current first-run seed is `[]`                                                                  |
| Scope creep (“just add UUID”)                    | Card non-goals; WIP discipline                                                                                    |
| shadcn primitives not yet integrated             | Keep this card on the documented contract; migrate the shared primitive layer in a dedicated UI-foundation change |
